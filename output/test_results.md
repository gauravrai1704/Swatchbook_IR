## Where positional information changes results vs. plain VSM

### Case study: "regular fit"
- VSM (bag-of-words) top-10 order: ['D076', 'D036', 'D004', 'D064', 'D056', 'D016', 'D024', 'D084', 'D096', 'D044']
- SDM (positional, ordered-bigram-aware) top-10 order: ['D004', 'D064', 'D024', 'D084', 'D044', 'D040', 'D100', 'D060', 'D023', 'D083']
- **Order changes starting at rank 1.** Documents promoted by SDM: ['D064', 'D024'] (ordered-bigram hit counts: {'D064': 2, 'D024': 2}). Documents demoted: ['D076', 'D036'] (ordered-bigram hit counts: {'D076': 0, 'D036': 0}).
- Reason: bag-of-words VSM assigns the same score to any document containing both query terms regardless of where they sit in the text. SDM adds credit when the terms occur *adjacent and in query order* (using the positional index), so a document where they form an exact phrase outranks one where they are merely both present but scattered across the description. The rank-shift badges on the phrase-search table above show this same effect directly against plain VSM.

### Case study: "festive wear" (result SET changes, not just order)
- VSM lnc.ltc result set: EMPTY -- see explanation below
- Exact phrase search result set: ['D005', 'D015', 'D025', 'D035', 'D045', 'D055', 'D065', 'D075', 'D085', 'D095']
- Rank-shift badges on those phrase results: ['NEW', 'NEW', 'NEW', 'NEW', 'NEW', 'NEW', 'NEW', 'NEW', 'NEW', 'NEW'] (expect all "NEW" -- VSM never ranked them)
- SDM result set (uses positional evidence even when unigram idf=0): ['D005', 'D015', 'D025', 'D035', 'D045', 'D055', 'D065', 'D075', 'D085', 'D095']
- **Explanation:** every one of the 100 documents in this corpus contains both of these words somewhere in its templated description (df=100 for each term), so idf = log10(N/df) = 0 for both, which makes every ltc query weight zero and VSM/BM25-style scoring unable to distinguish ANY document from any other -- a real bag-of-words retrieval fails to notice that the phrase is actually a meaningful, literal attribute description in a specific subset of products. The positional index is unaffected by idf and still finds the documents where the words occur as a genuine adjacent phrase, so the result SET (not merely its order) changes from empty to populated.
