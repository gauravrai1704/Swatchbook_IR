Under the hood

What’s actually happening here

Every product description is tokenized, stemmed (a from-scratch Porter stemmer), and stripped of stop-words, then indexed twice: a plain inverted index of term frequencies for the required lnc.ltc vector-space ranking, and a positional index recording exactly where each stemmed token sits, powering the phrase and proximity search on the second tab.

The other three ranking options are research-grounded extensions built on top of the same indexes: BM25 (Robertson & Zaragoza, 2009) for comparison against the required lnc.ltc weighting; the Sequential Dependence Model (Metzler & Croft, SIGIR 2005), which folds ordered/unordered positional evidence directly into the ranking score rather than only using it for phrase filtering; and a title-boosted ranker inspired by BM25F (Robertson, Zaragoza & Taylor, 2004), which rewards a query term appearing in a product’s title or category over the same term buried in body copy. Click “inspect score” on any result to see the term-level arithmetic.

Everything runs client-side in this page — the whole engine (indexing, all four rankers, phrase/proximity search, and a Levenshtein-distance typo-tolerant fallback) is under 500 lines of plain JavaScript with no server and no dependencies, so this file can be opened locally or hosted anywhere static files are served.

Beyond the core retrieval pipeline, the interface adds several layers of explanation in sequence: each result now includes a Google-style snippet — the highest query-term-density window of the product description, with matches highlighted inline. Next, the phrase and proximity views attach a rank-shift badge (▲/▼) that shows how much a document moved relative to plain VSM for the same query, giving a direct visual read on when positional evidence changes ranking and when a document appears only because of positional matches (marked as a gold NEW result). After that, the Relevance & NDCG tab lets you grade each candidate document on a 0–3 scale and recomputes NDCG@10 live for every ranker, so the evaluation is driven by your judgments rather than any hard-coded labels. Finally, the ranker controls include a Custom SMART-notation VSM builder: six dropdowns let you compose any tf.df.norm weighting scheme (natural/log/augmented/boolean/log-average term frequency × no-idf/idf/prob-idf × none/cosine/pivoted-unique/byte-size normalization, independently for documents and queries) so you can explore schemes beyond the required lnc.ltc and see how they re-rank the same corpus.
